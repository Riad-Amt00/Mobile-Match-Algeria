\section*{General Context}

Algeria's mobile telecommunications market is characterised by a triopoly consisting of three licensed operators: Mobilis, Djezzy, and Ooredoo. Together, these operators served more than 54~million mobile subscribers as of the first quarter of 2025 according to the most recent ARPCE observatory, a 4.4\,\% increase over the same quarter of the previous year \parencite{ARPCE2025, ARPCE2024}. Each operator regularly releases prepaid, postpaid, and data-only plans — varying in price, data volume, voice minutes, SMS allowances, validity periods, and network generation (4G or 5G). The resulting catalogue of offers grows continuously and changes frequently, making it increasingly difficult for consumers to identify the plan that best matches their individual needs and budget.

Despite the richness of the available supply, Algerian consumers currently lack a dedicated, automatically-updated comparator with personalised recommendations for mobile plans. One local platform addressing part of this need — Comparili.net, founded in 2020 — provides editorially-curated comparisons of mobile plans alongside other verticals (software, web hosting, banking cards), but no specialised mobile-plan platform with automated data collection and a multi-criteria recommendation engine exists at the national level. Operator websites themselves present only their own products. This information landscape forces users to visit multiple sites, manually record and compare figures, and rely on incomplete or outdated information when making purchasing decisions.

\section*{Problem Statement}

The central problem addressed by this work can be stated as follows: how can a neutral, regularly-updated web platform be designed and implemented to transparently aggregate all Algerian mobile offers, provide advanced filtering and side-by-side comparison tools, and deliver personalised recommendations tailored to each user's budget and usage profile?

Answering this question requires solving three interdependent sub-problems. First, offer data must be collected automatically and reliably, given the absence of public APIs from the operators. Second, a scoring model must translate a user's declared preferences into a ranked list of suitable plans. Third, all of these capabilities must be packaged in a responsive, accessible, and intuitive web interface suitable for a broad audience.

\section*{Objectives and Scope}

This project, carried out within the framework of the Licence en Métiers de l'Informatique at IFAG Alger, pursues five clearly defined objectives. The first objective is to develop a full-stack web application that enables users to browse, filter, and compare mobile plans from all three national operators. The second objective is to build an automated data-collection module capable of scraping offer data from operator websites and maintaining a normalised, up-to-date database. The third objective is to implement a recommendation engine that scores available plans against a user-defined profile and returns the three best-matched options. The fourth objective is to integrate data-visualisation tools — including comparative bar charts, a savings calculator, and a structured search interface — to support informed decision-making. The fifth objective is to implement an in-app notification system that alerts registered users to new offers and to relevant changes in the catalogue.

The scope of this work covers the three Algerian mobile operators (Mobilis, Djezzy, Ooredoo) and the plan types currently offered: prepaid, postpaid, and data-only. Fixed-line internet, bundled home offers, and international roaming plans fall outside the scope of this version and are identified as future extensions in the general conclusion.

\section*{Methodology}

The methodology adopted in this work combines a documentary research phase with an iterative development cycle. The needs-analysis phase relies on secondary sources — the ARPCE \textit{Rapport annuel sur le marché des télécommunications}, GSMA Intelligence reports for the MENA region, the DataReportal \textit{Digital 2025: Algeria} survey, and the Mordor Intelligence sector analysis — to characterise the Algerian consumer's environment, average data consumption, market shares, and network generation distribution \parencite{ARPCE2024, GSMA2024, DataReportal2025, Mordor2025}. These officially-published indicators substitute for a primary user survey within the project timeline and provide a defensible empirical foundation for the requirement set.

The technical architecture was designed around the \textit{Next.js~16} full-stack framework, which allows the front-end interface and the back-end API routes to be developed within a single codebase. Data persistence is managed through \textit{Prisma~ORM} backed by a \textit{SQLite} database, chosen for its zero-configuration deployment footprint and its sufficiency for the project's actual scale. Automated offer collection is handled by a custom scraping module that runs on a scheduled basis with snapshot-based regression testing. The recommendation engine applies a tiered-ranking model: hard filters first remove offers incompatible with the user's categorical constraints, then the user's primary priority determines a tier of remaining offers and the secondary priority orders the offers within that tier.

\section*{Thesis Structure}

The remainder of this thesis is organised into four chapters. Chapter~1 surveys the state of the art, covering the Algerian telecom market, existing comparison platforms, web data aggregation techniques, recommendation systems, and the modern web stack selected for this project. Chapter~2 presents the requirements analysis and system design, including the secondary-research methodology, use-case diagrams, the data model, the system architecture, and the technology choices. Chapter~3 describes the full implementation of the platform, detailing the scraping module and its validation infrastructure, the REST API, the tiered-ranking recommendation engine, the structured search interface, the comparative visualisation, the savings calculator, the notification system, and the security mechanisms. Chapter~4 evaluates the platform against the five project objectives, validates the recommendation engine on representative test cases, reports the load-testing results, documents the identified limitations, and summarises the documentation produced. The work closes with a general conclusion that summarises the contributions, acknowledges limitations, and outlines perspectives for future development.
