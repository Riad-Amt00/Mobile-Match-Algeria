\section*{Problem Recall and Summary of Contributions}

This work set out to address a concrete gap in the Algerian digital-services landscape: the absence of a dedicated platform that allows consumers to compare mobile plans across all three national operators with automated data collection and personalised recommendations. While one local multi-vertical comparator (Comparili.net) addresses part of this need with editorial coverage and user reviews, no specialised mobile-plan platform with deep multi-criteria features currently exists; Algerian users still navigate three separate operator websites and reconcile heterogeneous formats by hand. The five objectives established at the outset of this project --- a full-stack web application, an automated scraping module, a personalised recommendation engine, integrated data-visualisation tools, and an in-app notification system --- were designed collectively to eliminate this gap.

The work produced five concrete contributions, matching the five FICHE objectives:

\begin{enumerate}
  \item A functional web application on Next.js~16 serving a catalogue of ninety-seven mobile plans from Mobilis, Djezzy, and Ooredoo, with multi-criteria filters, a structured search interface (parsed-token chips), a side-by-side comparison page with per-metric bar charts, a savings calculator, and a guided help / tutorial page.
  \item A modular scraping pipeline fetching and normalising offer data from the three operator websites with retry / backoff, snapshot-based regression tests, per-family deactivation, and a verified fallback dataset for the three plan families that cannot be automatically parsed.
  \item A two-layer recommendation engine combining categorical hard filters (operator, plan type, network, calls, SMS, budget ceiling) with a tiered ranking on the user's primary and secondary continuous priorities (price, data); the design guarantees the stated priority strictly dominates the result.
  \item A complete admin dashboard providing platform statistics, an operator-health panel, per-family plan breakdowns, and a detailed scrape history.
  \item A split-stream in-app notification system distinguishing user notifications (\texttt{new\_offer}, \texttt{price\_drop}, \texttt{recommendation}) from administrator notifications (\texttt{scrape\_complete}, \texttt{scrape\_failed}).
\end{enumerate}

\noindent The platform is supported by 99 unit tests and a load-test campaign sustaining over 200~req/s on the browse endpoint and 60~req/s on the recommendation endpoint with zero errors --- approximately 30$\times$ the realistic peak load at the current scale (full results in Ch4 §4.3).

\section*{Limitations}

Six limitations of the current version:

\begin{enumerate}
  \item \textbf{SQLite scalability ceiling} --- requires migration to PostgreSQL before high write-concurrency; Prisma's adapter system makes this a configuration change.
  \item \textbf{Scraper fragility} --- operator-side layout changes break the parser until manually repaired; snapshot tests catch the failure immediately.
  \item \textbf{Flattened \guillemotleft{}unlimited\guillemotright{} scope} --- calls and SMS modelled as binary; on-net vs all-network distinction lives only in feature text.
  \item \textbf{Strict search parser} --- no typo tolerance, no BM25-style relevance ranking.
  \item \textbf{Absence of a formal user study} --- the principal limitation; technical validation only.
  \item \textbf{Single-machine evaluation} --- no public-host deployment within the project timeline.
\end{enumerate}

\section*{Perspectives}

Six directions for future development, ordered by priority:

\begin{enumerate}
  \item \textbf{Formal usability study} (50+ testers, SUS-style instrument) addressing limitation~5.
  \item \textbf{Public cloud deployment} and platform-specific benchmarking, addressing limitation~6.
  \item \textbf{Mobile and tablet responsive polish} for the form factor most consumers actually use.
  \item \textbf{Fully-live scraping of the three fallback families} (Djezzy ZID, Djezzy IZZY!, Mobilis Revolution) through a paid scraping API and a commercial Cloud Vision LLM, with administrator alerts on degradation.
  \item \textbf{Integration tests} at the API-route and end-to-end level, complementing the unit-test suite.
  \item \textbf{Collaborative-filtering layer} once interaction data accumulates \parencite{hu2008collaborative, AdomaviciusTuzhilin2005}, implementable inside Node.js or as a thin Python service.
\end{enumerate}

\noindent Further extensions --- fixed-line broadband, bundled home-and-mobile plans, a public REST API for third parties, full-Arabic scraping --- would extend the platform's reach.
