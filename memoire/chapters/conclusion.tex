\chapter*{General Conclusion and Perspectives}
\addcontentsline{toc}{chapter}{General Conclusion and Perspectives}
\markboth{General Conclusion and Perspectives}{General Conclusion and Perspectives}

This work set out to address a concrete gap in the Algerian digital services landscape: the absence of a dedicated platform that allows consumers to compare mobile plans across all three national operators with automated data collection and personalised recommendations. Algerian users still navigate three separate operator websites and reconcile heterogeneous formats by hand, and the only local multi vertical comparator covers mobile plans as one section among several without automated scraping or a recommendation engine. Mobile Match Algeria fills that gap.

Chapter~1 framed the core technical disciplines that this work draws on, web data aggregation, web scraping, recommendation systems, and structured search engines for small structured catalogues, together with the comparison, notification, and interface design concerns, and situated them within the Algerian mobile telecommunications market and the international comparison platform landscape. Chapter~2 translated that review into a complete requirements set, a UML use case model around three actors, a class diagram showing the eight application entities with their attributes, operations, and associations, a three tier system architecture, and a justified technology stack. Chapter~3 documented the running implementation: a Playwright based scraping pipeline with snapshot validation, a REST API exposing the data layer, a two layer recommendation engine combining categorical hard filters with TOPSIS multi criteria ranking, a structured search engine that translates free text queries into typed chips, a comparative visualisation surface, and a split stream notification system distinguishing user facing alerts from administrator alerts. Chapter~4 validated the implementation against the five FICHE objectives. The platform serves a catalogue of eighty three mobile plans collected automatically from Mobilis, Djezzy, and Ooredoo, with multi criteria filters, a side by side comparison page, an integrated savings indicator on each recommended plan, and a guided help / tutorial page. All five objectives stated in the subject fiche are met by the running system.

\section*{Perspectives}

The work as it stands is operational and complete with respect to the FICHE objectives. The following directions describe upgrades that would extend its reach and bring it closer to a production deployment serving the wider public:

\begin{enumerate}
  \item \textbf{Web scraping for image only plan families.} Two families, Mobilis Revolution and Djezzy iZZY!, publish their prices exclusively inside carousel images with no machine readable text, so they cannot be parsed by HTML based scrapers or reliably verified by hand. They are therefore excluded from the catalogue rather than transcribed manually, which is precisely what lets the platform present a fully live, machine readable catalogue with no hand entered data. In the meantime these two families remain available directly on the operator websites, and the application signals this to the user so the information is not lost. Re-including them is a clear future direction, either through optical character recognition, which proved unreliable on the multilingual carousels, or through a commercial computer vision service or a paid scraping API, which would let those families be collected live.
  \item \textbf{Public cloud deployment.} The application is currently exercised in production mode on the development machine. A public deployment to a managed Node.js host (Vercel, Railway, Fly.io, or a self managed VPS) would make the platform reachable for real Algerian users; the Next.js / Prisma / SQLite stack is portable to any Node.js host and the deployment is a configuration change, not a code change.
  \item \textbf{Formal usability study with external testers.} Validation in this work was analytical, derived from the system's specified behaviour rather than from end user feedback. A formal study with external testers, using a standardised instrument such as the System Usability Scale \parencite{NielsenNorman2023}, would produce the empirical user satisfaction signal that the project timeline could not accommodate.
  \item \textbf{Mobile and tablet responsive polish.} The current interface is tuned for desktop browsers. Tightening the responsive breakpoints for small screens and adapting the comparison page for narrow viewports would broaden accessibility to the form factor most Algerian consumers actually use.
  \item \textbf{Refined modelling of unlimited calls and SMS.} The current data model represents calls and SMS as binary attributes. A scoped attribute distinguishing on net (\guillemotleft{}illimité vers Djezzy\guillemotright{}) from all network unlimited bundles would let the recommendation engine reward plans whose call scope actually matches the user's contact graph.
  \item \textbf{Collaborative filtering layer once user data accumulates.} The cold start framing of Chapter~1 §1.3 leaves an open path: once interaction histories build up, a collaborative filtering layer or a hybrid model \parencite{hu2008collaborative, AdomaviciusTuzhilin2005, BernardiKamps2016} could be added alongside the existing content based engine to surface plans the user has not explicitly considered.
\end{enumerate}

Taken together, these perspectives describe a credible path from the present operational prototype to a production grade comparator serving the wider Algerian public.
